# プレミアリーグ vs ラ・リーガ ゴール時の歓声の音響比較

## 1. 背景・目的

プレミアリーグとラ・リーガのゴール時の歓声を聴き比べると、プレミアは「イェーイ」に近い明るい歓声、
ラ・リーガは「ウォオ」に近い低くこもった歓声に聞こえる、という印象があった。この違いを音響特徴量で
定量的に検証する。

## 2. 結論(先に要約)

サンプル数17件(プレミア9件・ラ・リーガ8件)の分析で、以下の点において**統計的に有意な差**が確認された。

- プレミアの歓声は**スペクトル的に明るい**(スペクトル重心・ロールオフ・帯域幅が有意に高い)
- プレミアの歓声は**立ち上がりが速い**(ゴール後、音量ピークに達するまでの時間が短い)
- フォルマント解析(F1・F2)でも、プレミアの方が**より前寄り・開口寄り**の母音特性を示した

これは最初の聴感上の印象(プレミア=「イェーイ」/明るい、リーガ=「ウォオ」/低く暗い)を裏付ける結果である。

## 3. データソースの変遷

最初は個別の試合ハイライト動画を使ったが、以下の問題が順に発覚し、最終的なソースにたどり着いた。

| 段階 | ソース | 問題点 |

| 1 | LaLiga公式ハイライト(Racing 3-2 Elche) | 実況なし・良質だったが n=3 のみ |
| 2 | プレミア日本語実況ハイライト(U-NEXT) | ゴール瞬間に実況の絶叫が重なり、ピッチ解析が実況の声を拾ってしまう |

## 4. 解析パイプライン

### 4.1 音声取得

- `yt-dlp` で音声のみをWAV形式で抽出(動画ファイル自体は保存していない)
- `ffmpeg` で各ゴールタイムスタンプの前後(タイムスタンプ-1秒 〜 +6秒、計7秒)を切り出し

### 4.2 音量ピーク検出とアタック/ディケイ

- `librosa` でRMSエンベロープを計算
- **重要な修正点**: 当初は7秒クリップ全体からRMS最大値の時刻を「ゴール歓声のピーク」としていたが、
  一部のクリップでスタジアムの演出音(ゴールジングル/サイレン風の低周波の周期音)が歓声より後に
  クリップ内で発生し、それが誤ってピークとして検出されるケースが2件見つかった
  (`ucl_laliga_atletico2`, `ucl_laliga_realmadrid3`)。スペクトログラムで確認したところ、
  4秒以降に非常に強い低周波(100〜150Hz帯)のトーン成分が出現しており、これが原因と判明。
  **対策として、ピーク探索をクリップ最初の4秒以内に制限**した(ゴールタイムスタンプはクリップ内
  1秒地点に相当するため、実質「ゴール後3秒以内」を探索対象とする)
- 立ち上がり時間: ピーク値の10%地点からピークまでの時間
- 減衰時間: ピーク値から50%まで下がるまでの時間(多くのクリップでは7秒以内に半減せず、算出不可)

### 4.3 スペクトル特徴量(librosa)

ピーク時刻を中心とした解析窓(ピーク-0.5秒 〜 +2.5秒)に対して算出。

- スペクトル重心 (spectral centroid)
- スペクトルロールオフ 85% (spectral rolloff)
- スペクトル帯域幅 (spectral bandwidth)
- スペクトル平坦度 (spectral flatness)
- ゼロ交差率 (zero crossing rate)
- 基本周波数 F0(pYINアルゴリズム、有声フレーム率も記録)

### 4.4 フォルマント解析(母音特性)

- `praat-parselmouth`(PraatのPython版)のBurg法でF1・F2を推定
- 同じくピーク中心の解析窓に対して算出
- 群衆音は単一話者を前提としたLPC解析には理論上不向きだが、「集団としてのスペクトル包絡の
  山」として近似的に解釈できる、という前提のもとで実施(詳細は7章の限界を参照)

### 4.5 統計検定

- Welchのt検定(等分散を仮定しない)でプレミア群とリーガ群を比較

## 5. 結果(最終版、ピーク検出修正後)

| 指標 | プレミア (mean±SD) | リーガ (mean±SD) | p値 |
|---|---|---|---|
| 立ち上がり時間 | 1.51 ± 0.58 秒 | 2.31 ± 0.49 秒 | 0.011 |
| スペクトル重心 | 1987 ± 94 Hz | 1530 ± 108 Hz | <0.0001 |
| ロールオフ85% | 3367 ± 200 Hz | 2580 ± 208 Hz | <0.0001 |
| スペクトル帯域幅 | 1604 ± 81 Hz | 1355 ± 111 Hz | 0.0003 |
| F0中央値 | 871 ± 18 Hz | 843 ± 29 Hz | 0.049 |
| F1中央値(フォルマント) | 938 ± 32 Hz | 867 ± 26 Hz | 0.0003 |
| F2中央値(フォルマント) | 1727 ± 29 Hz | 1514 ± 62 Hz | <0.0001 |

すべての指標で、プレミアがリーガより有意に高い値を示した。

### 解釈

- **スペクトル重心・ロールオフ・帯域幅**: プレミアの歓声は高域成分が多く、音色として明るい。
  リーガは低域寄りで、こもった/暗い音色
- **立ち上がり時間**: プレミアは瞬間的に立ち上がる歓声、リーガはじわっと盛り上がる傾向
- **F1・F2(母音特性)**: 両リーグとも典型的な「エ」や「オ」というより開口母音「ア」に近い
  領域だが、相対的にはプレミアがより前寄り(「エ」方向)、リーガがより後ろ寄り(「オ」方向)。
  これは「イェー」対「ウォー」という最初の印象の方向性と一致する
- **F0**: 群衆音への適用は本質的に不安定(後述)なため、他の指標ほど頑健ではない。有意ではあるが
  p値はギリギリ(0.049)

## 6. 環境構築メモ(WSL / Windows)

分析はすべてWSL(Debian)上のPythonで実施した。主な技術的つまずきと対処:

- WSLの `python3`(pyenv経由)は `_bz2` モジュールがビルド時に欠落しており、`librosa` が使用する
  `pooch` 経由で `ModuleNotFoundError: No module named '_bz2'` が発生。システムの `/usr/bin/python3`
  (Debianパッケージ版、bz2利用可)に切り替えて解決
- システムPythonは PEP 668 (externally-managed-environment) により pip が制限されていたため、
  `--break-system-packages --user` で個人領域にインストール
- `pip install demucs` が依存関係解決で長時間(20分以上)スタック。原因はGPU版PyTorch
  (CUDA関連ライブラリ込みで数GB規模)を解決しようとしていたため。CPU専用ビルド
  (`--index-url https://download.pytorch.org/whl/cpu`)を明示指定して解決
- 上記の理由により、最終的にDemucsによる音源分離は主要な結果には使用せず
  (実況なしソースが見つかったため不要になった)

使用した主なライブラリ: `yt-dlp`, `ffmpeg`(`imageio-ffmpeg`), `librosa`, `soundfile`, `numpy`,
`scipy`, `matplotlib`, `praat-parselmouth`

## 7. 限界・注意点

- **サンプル数**: n=9 vs n=8 とまだ少ない。UEFA公式の「ベストゴール集」という性質上、
  派手で盛り上がったゴールに選抜されているバイアスがある可能性がある
- **フォルマント解析の妥当性**: LPC由来のフォルマント推定は本来1人の声道を前提とした手法。
  数万人が同時発声する群衆音への適用は、個々のフォルマントではなく「集団としてのスペクトル
  包絡のピーク」を見ていると理解すべきで、真の意味での音声学的フォルマントとは性質が異なる
- **F0(ピッチ)推定の不安定性**: pYINによるピッチ推定は、群衆の歓声のような非周期的・
  ブロードバンドな音には本質的に不向き。有声フレーム率が低いクリップでは、少数のフレームから
  計算された中央値が外れ値になりやすい(本調査でも2件、ピーク検出の誤りに起因する外れ値が発生し、
  修正が必要だった)
- **単一シーズン・単一大会**: チャンピオンズリーグの試合に限定されているため、リーグ戦の
  通常運用時の雰囲気とは異なる可能性がある(観客動員、注目度などが平常時と異なる)

## 8. 今後の発展案

- サンプル数を増やす(通常のリーグ戦のハイライトから、実況なし音源を追加で探す)
- ベストゴール集ではなく、通常のフルマッチ映像から無作為にゴールを抽出し選抜バイアスを減らす
- フォルマント解析の妥当性を検証するため、個々のファンの声を近接マイクで収録したデータと比較する
- 減衰時間(歓声が収まるまでの時間)も比較指標に加える(今回は多くのクリップで7秒以内に
  半減せず算出不可だった)
