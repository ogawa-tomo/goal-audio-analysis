# goal-audio-analysis

ゴール時の歓声など、群衆の音声データを解析するためのツール。

- **`features.py`**: 1クリップの音声から音響特徴量(スペクトル重心・ロールオフ・帯域幅・
  平坦度・ゼロ交差率・F0・フォルマントF1/F2、およびゴール前後の増分指標)を抽出する。基準点は
  サイドカーファイル(`<clip>.mark.json`)の`onset_marked_time_s`(歓声が盛り上がり始めた瞬間、
  人間が確認。`scripts/mark_onset_moment.py`で指定)。マークされていないクリップは解析できない
  (エラーになる)。以前は音量ピーク(`human_marked_time_s`、`scripts/mark_goal_moment.py`で
  指定)を基準にした立ち上がり時間・減衰時間も算出していたが、常に大きな音が続くクリップでは
  測定の前提自体が成立しないことが分かり、分析から除外した(`reports/premier_vs_laliga.md`
  4.2節・7章参照)
- **`onset.py`**: `scripts/mark_onset_moment.py`が使う、立ち上がり瞬間の候補検出ロジック
  (前後1秒ずつのスペクトル形状変化=コサイン距離を計算し、局所的な極大点を候補として列挙する)
- **`compare.py`**: 特徴量(dictのリスト)を2群受け取り、Welchのt検定で比較する。音声処理には
  依存しないので、音声以外の2群比較にも流用できる
- **`extract.py`**: `ffmpeg`を使ってローカルの音声ファイルからクリップを切り出す。**音声データ
  そのものの取得(ダウンロード・録音等)はこのツールの対象外**(下記「音声データの用意について」参照)
- **`plotting.py`**: 比較結果の棒グラフ・母音(F1-F2)図を生成する
- **`cli.py`**: 上記をコマンドラインから呼び出せるようにするエントリポイント

## セットアップ

```bash
pip install -e .
```

`ffmpeg`実行ファイルもPATH上に必要(クリップ切り出しに使用)。

## 音声データの用意について

このツールは「手元にある音声ファイルからクリップを切り出して解析する」ところから始まる。
**音声ファイルそのものをどう用意するかはツールの対象外**であり、ソースごとに以下の点に注意する。

- **YouTube等の動画サイトが原音源の場合**: 多くのサービス(YouTube含む)は利用規約で
  公式のダウンロード機能以外でのダウンロードを禁止している。**通常の再生(ストリーミング)を
  行いながら、OSのループバック録音機能や画面録画ツールでシステムの音声出力を録音する方法**
  を使うこと。この方法であれば「許可されていない方法でのダウンロード」という規約条項には
  触れない(通常の視聴と同じリクエストしかサーバーに送っていないため)。ただし著作権法上の
  整理は別途必要になるので、下記「著作権・利用規約について」を参照
  - 録音時はOSの音声エフェクト(ラウドネス補正・空間オーディオ等)やAGC(自動ゲイン調整)・
    ノイズ抑制を無効化し、システム音量を固定しておくこと。これらが有効だとスペクトル特徴量
    (重心・ロールオフ等)やRMSエンベロープ(立ち上がり時間・ピーク検出)が歪む可能性がある
  - 録音・保存部分だけを自動化する補助スクリプトを [`scripts/loopback_record.py`](scripts/loopback_record.py)
    に用意している。**現時点ではWindows専用**(WASAPIループバックを利用しており、
    WSL内からはOSのオーディオミキサーに直接アクセスできないため実行不可。macOSも
    CoreAudioにはWASAPI相当のループバック機構がなく、`BlackHole`等の仮想オーディオ
    デバイスの追加セットアップとスクリプト側の対応が別途必要なため、現状未対応)。
    実行はWSLではなくWindows側のPythonで行うこと。ブラウザでの再生開始タイミングだけは
    手動で合わせる想定(完全自動化はしていない)。使い方はスクリプト冒頭のdocstringを参照。
    事前に `pip install -r scripts/requirements.txt`(Windows側のPython環境に)が必要
  - **録音した内容の中で、実際にどこが目的のイベント(ゴール)の瞬間かは、人間が指定する**。
    [`scripts/mark_goal_moment.py`](scripts/mark_goal_moment.py)を使い、`python
    scripts/mark_goal_moment.py <clip.wav> <時刻>`(秒数、または`分:秒`形式)のように渡すと、
    その時刻をサイドカーファイル(`<clip>.mark.json`)に`human_marked_time_s`として保存する。
    **ただし、現在`goal-audio analyze`が実際に解析の基準点として使うのは`onset_marked_time_s`
    (歓声が盛り上がり始めた瞬間)であり、`human_marked_time_s`は使われていない**(経緯:
    `reports/premier_vs_laliga.md`4.2節を参照。当初は音量ピーク=`human_marked_time_s`を
    基準にしていたが、後から立ち上がりの瞬間を基準にする設計に切り替えた)。
    `onset_marked_time_s`は[`scripts/mark_onset_moment.py`](scripts/mark_onset_moment.py)で
    指定する。`python scripts/mark_onset_moment.py <clip.wav>`とすると、スペクトル形状の
    変化量から立ち上がり候補を検出して一覧表示するので、実際に聴いて確認したうえで
    `--pick <番号>`で選ぶと`onset_marked_time_s`が保存される(候補がどれも正しくない
    場合は`--time <秒数>`で自由に指定することもできる)。マークされていないクリップは
    解析できない(エラーになる)。

    (**設計の経緯**: 音量が最大になる瞬間や、音量の変化が最も急な瞬間をアルゴリズムで自動検出
    する方式を何通りも試したが、いずれも実際のデータで「ゴール前のチャンスシーンへの反応の方が
    音量・変化率ともに本物のゴールより大きい」「ゴールの盛り上がりが緩やかな持続区間で、目立つ
    山がない」といった実例に繰り返し失敗した。複数の候補をアルゴリズムが提示し人間が選ぶ、という
    折衷案も試したが、正解がそもそも候補に含まれないケースがあり不十分だった。結論として、
    **人間が音声を注意深く聴いて特定した瞬間を、そのまま使う**のが最も確実だった。
    ただし「一度だけ再生して反応した瞬間をそのまま申告する」というやり方だと、反応速度の
    ズレがそのまま計測誤差になる。これを避けるため、ブラウザの`<audio>`要素を使った簡易ツール(自作、リポジトリ外で管理)
    のような0.01秒精度で再生位置を確認できるツールで、**巻き戻し・微調整を繰り返して
    確信を持てる時刻に絞り込んでから確定する**、という運用を前提にしている。このスクリプト
    自体はOS依存がないため、WSL側からでも実行できる)
- **WOWOW・U-NEXT等の有料配信サービスが原音源の場合**: 利用規約でストリーミングの録画・
  録音自体を明確に禁止していることが多く、YouTubeより制約が厳しい。BS放送等、テレビ放送を
  対応レコーダーで録画したもの(コピーワンス等の正規のコピー制御下にある録画)であれば、
  そこからのループバック録音は比較的問題が少ないと考えられるが、配信サービス(VOD)からの
  録画・録音は規約違反となる可能性が高いため避けること
- **Creative Commons等でライセンスが明示された音源(Freesoundなど)の場合**: ライセンス条件
  (帰属表示の要否、商用利用可否など)を確認した上でダウンロードして問題ない。実際に使用した
  音源とライセンスの記録例は `data/raw/SOURCES.md` を参照(音源ファイル自体はGit管理外)

## 使い方

### 用意すべき音声の範囲について

解析の基準点は人間が確認した時刻そのものであり、アルゴリズムによる自動検出は行わない。
したがって`extract-clip`に渡す**タイムスタンプの精度自体は重要ではない** -- クリップの
どこかにゴールの瞬間が収まっていれば、あとで正確な時刻を指定すればよい。

ただし、以下の点には注意する。

- **クリップには、ゴールの瞬間の前後に十分な余裕を持たせること**。基準点(立ち上がりの瞬間)
  から後ろ3秒間はスペクトル特徴量の解析窓として直接使われるため、最低限その範囲は必要。また
  ゴール前のチャンスシーンなど紛らわしい展開が含まれる場合、それも含めて聴けた方が正しい瞬間を
  判断しやすいため、前後とも数秒の余裕を持たせておくのが望ましい(目安: 前に5秒、後ろに8秒程度)
- ループバック録音の場合、`loopback_record.py`のカウントダウン終了と同時に録音が始まるため、
  「ゴールの何秒前から録音するか」は一時停止位置と再生ボタンを押すタイミングで決まる。厳密な
  計算は不要になったが、余裕を持たせる意味で、一時停止位置は**ゴールの5秒前**、
  `--duration`は**14秒**程度を推奨する
- **再生ボタンは、カウントダウンがちょうど終わるタイミングではなく、少し早めに押すこと**。
  多くの録音は冒頭が完全な無音から始まりがちで(録音開始とほぼ同時に再生ボタンを押すと、
  実際に音声が流れ始めるまでにわずかなラグが生じるため)、早めに押しておけば録音開始時点で
  既に音声が流れている状態にできる。前後2秒の解析窓には十分な余裕があるので、多少早く
  押しすぎても問題ない
- **ゴール前後の区間に、歓声そのものより目立って大きい音(実況の絶叫・演出音等)が
  入っていないか**、可能であれば事前に確認しておく(実況ありの音源を避け、スタジアムの
  生音に近いものを選ぶのが望ましい。詳しくは「音声データの用意について」を参照)

### 実行手順

```bash
# 1. (音声データを用意する。上記の目安と「音声データの用意について」を参照。ここでは
#    data/raw/source.wav に用意できているものとする)

# 2. ゴールタイムスタンプ(おおよその秒数でよい)を中心にクリップを切り出す
goal-audio extract-clip data/raw/source.wav data/clips/goal1.wav 74

# 3. ゴールの立ち上がりの瞬間を指定する。候補を提示させ、聴いて確認してから選ぶ
python scripts/mark_onset_moment.py data/clips/goal1.wav
python scripts/mark_onset_moment.py data/clips/goal1.wav --pick 1
# (他のクリップも同様に、1つずつマークする)

# 4. 特徴量抽出(複数クリップまとめて。マークしていないクリップはスキップされる)
goal-audio analyze data/clips/premier_*.wav -o results/premier_features.json
goal-audio analyze data/clips/laliga_*.wav -o results/laliga_features.json

# 5. 2群比較(表を標準出力 + グラフをresults/以下に保存)
goal-audio compare results/premier_features.json results/laliga_features.json \
  --label-a Premier --label-b LaLiga -o results/
```

Pythonから直接呼ぶ場合:

```python
from goal_audio_analysis import features, compare, plotting

f = features.analyze_clip("data/clips/goal1.wav")

group_a = [features.analyze_clip(p).to_dict() for p in premier_clips]
group_b = [features.analyze_clip(p).to_dict() for p in laliga_clips]
comparisons = compare.compare_groups(group_a, group_b, label_a="Premier", label_b="LaLiga")
print(compare.format_table(comparisons))
```

## 既知の注意点

- 解析の基準点(`onset_marked_time_s`)は`scripts/mark_onset_moment.py`が提示する候補から
  人間が選んだ時刻そのものであり、選んだ後にアルゴリズムによる自動補正は一切行わない。
  候補は聴いて確認してから選ぶこと(候補検出ロジックの詳細は`onset.py`のdocstring・
  `reports/premier_vs_laliga.md`4.2節を参照)
- `loopback_record.py`は、録音バッファの取りこぼし(`soundcard`の"data discontinuity"警告)を
  検知して回数を表示する。警告が出た場合はクリップを目視確認(スペクトログラム等)するか、
  再録音を検討すること(クリック状のノイズが、マークすべき瞬間の判断を妨げることがある)
- フォルマント(F1/F2)解析はPraat(Burg法)を使用しているが、本来1人の声道を前提とした手法。
  群衆音への適用は「集団としてのスペクトル包絡のピーク」の近似であり、厳密な音声学的
  フォルマントではないことに留意
- F0(pYIN)は群衆のブロードバンドな歓声には本質的に不安定。有声フレーム率(`voiced_fraction`)
  が低いクリップのF0値は参考程度に扱うこと

詳しい調査記録は [`reports/`](reports/) を参照。

## 関連研究

「サッカーの国別歓声を音響学的に(スペクトル解析等で)比較した研究」はほぼ見当たらなかったが、
隣接する分野に以下のような先行研究がある。

- **Nicolai Jørgensgaard Graakjær, *Popular Music and Football*, Cambridge University Press, 2026.**
  イングランド・ドイツ・スペイン・デンマークのスタジアムにおける歌・チャントのパターンを、
  過去10年分のケーススタディを基にマッピングした研究。イングランドは自発的・即興的な集団
  歌唱、ドイツはドラムと指揮者主導の組織的・持続的な歌唱、といった国ごとの違いを報告している。
  ただし音響解析(スペクトル分析等)は行っておらず、社会学・音楽学的な「歌の構造・組織性」の
  分析であり、今回のアプローチ(スペクトル重心・フォルマント等の信号処理的定量化)とは
  手法が異なる
- **Ponsonnet, Pisanski, Coupé et al., "Vowel signatures in emotional interjections and
  nonlinguistic vocalizations expressing pain, disgust, and joy across languages,"
  *Journal of the Acoustical Society of America*, 2024.**
  131言語の間投詞(感嘆詞)の母音をフォルマント(F1/F2)で比較し、感情のカテゴリ(苦痛・嫌悪・
  喜びなど)ごとに言語をまたいで一貫した「母音シグネチャー」が存在することを発見した研究。
  「感情発声をフォルマントで比較する」という手法は今回のフォルマント解析とほぼ同じだが、
  対象は個人の間投詞発声であり、群衆の歓声ではない
- **スタジアムの騒音レベル計測研究**(例: ミシガン大学スタジアムでのビームフォーミング測定、
  大学フットボールにおける騒音レベル評価): dB値や周波数帯ごとのエネルギー分布を測定して
  いるが、目的はスタジアム単体の音響工学(騒音対策・シミュレーション)であり、国・リーグ間の
  比較ではない
- **サッカー中継のハイライト自動検出研究**(観客の歓声スパイクを検出してゴールシーンを自動
  抽出する手法): 今回の「RMSピーク検出」と手法的に近いが、目的は「どこがハイライトか」の
  検出であって、歓声の音色そのものを比較することではない

今回行った「フォルマント解析でリーグごとの歓声の母音的特徴を比較する」というアプローチは、
上記の社会学的なファン文化研究と音声学的な感情発声研究の中間に位置する、比較的ニッチな
切り口だと考えられる。同じ組み合わせでの先行研究は見当たらなかった。

## 著作権・利用規約について

- 以前のバージョンでは`extract.py`に`yt-dlp`を使ったYouTube直接ダウンロード機能を含んでいたが、
  YouTubeの利用規約(公式のダウンロード機能以外でのダウンロード禁止)に抵触する行為を助長する
  コードであったため**削除した**。音声データの用意方法は上記「音声データの用意について」を参照
- **`data/`以下の音声ファイルはGit管理に含めない**(`.gitignore`)。取得した音声・切り出した
  クリップを外部に再配布・公開しないことを設計上の前提にしている
- 特徴量抽出(スペクトル重心・F0・フォルマント等の数値算出)自体は、日本の著作権法30条の4
  (著作物を「享受」する目的でない利用=情報解析)により、権利者の許諾なく行える可能性が高い。
  ただし、これは法的助言ではなく一般的な整理であり、個別のケースについて確信が持てない場合は
  専門家に確認すること
- スペクトログラム画像など、特定の音声から直接生成した視覚的な成果物を公開する場合は、
  「引用」(著作権法32条)の要件(公表済みの著作物であること、自分の著作物が「主」・引用部分が
  「従」の関係であること、必要最小限の範囲であること、出所明示)を満たすよう注意する
- 上記の理由から、本リポジトリは**Privateで運用**している。Publicにする場合は、音声非公開の
  徹底と、視覚的な成果物(スペクトログラム等)の要否を改めて見直すこと
